# firmware / esp32c3-bmp581

ESP32-C3 + BMP581 + WS2812B × 5 のファームウェア（Arduino スケッチ）です。

スケッチ: [`esp32c3-bmp581.ino`](esp32c3-bmp581.ino)（このフォルダを、Arduino IDE で開きます）

ビルドせずに使う場合は、[書き込みツール](https://ksasao.github.io/pressure-monitor/esp32c3-bmp581/flasher/)から、ブラウザで書き込めます。リリースの作り方は [RELEASING.md](../../RELEASING.md) を見てください。ファームウェアのバージョン（リリース日）は [`version.h`](version.h) にあり、起動時のシリアル、設定ページ、ハブの画面に表示されます。

## ファイル構成

機能ごとに、ファイルを分けています。`.h` が他のモジュールへの窓口（使い方の説明つき）で、`.cpp` が中身です。

| ファイル | 内容 |

| `display.h` / `.cpp` | LED の表示（履歴、描画、状態表示） |

| `battery.h` / `.cpp` | 電池電圧 |

| `logging.h` / `.cpp` | シリアルへの出力（`class SerialLog`）と、性能計測（`class PerfStats`） |

| `led_types.h` | FastLED の型を使うためのヘッダ |

依存の向きは、`.ino` → 各モジュール → `config.h` と `settings.h` です。`high_pass_filter` と `palette` は計算だけ、`settings_page` は文字列の組み立てだけで、通信や LED には触れません。

### Qwiic にセンサを足すとき

Qwiic コネクタ（I2C）に別のセンサを接続して、拡張することを想定した作りにしています。

- **`HighPassFilter`**: センサ（チャンネル）ごとにインスタンスを作ります。状態を持つ計算ですが、Arduino にも設定にも依存しません。
- **`SerialLog`**: 1 行を出すだけの汎用の出力です。センサごとに、その CSV の行を作って、同じ `SerialLog` に書きます（気圧の例は、`.ino` の `logPressure()`）。
- **`Button`**: ピンと長押しの時間をコンストラクタで受け取るので、別のボタンにも使えます。

I2C の初期化（`Wire.begin()`）は、今は `sensor.cpp` の `sensorBegin()` の中にあります。2 つ目のセンサを足すときは、I2C のバスの初期化を、センサとは別の場所に移すと、整理しやすくなります。

## ボード設定

| 設定 | 値 |
|---|---|
| Board | ESP32C3 Dev Module |
| USB CDC On Boot | **Enabled**（Disabled だと Serial が出ません） |
| Partition Scheme | **No OTA (2MB APP/2MB SPIFFS)**（既定のままだと、プログラムが入りません） |
| Flash Size | 4MB (32Mb)（既定のまま） |

**フラッシュの割り当ては、スケッチのフォルダにある [`partitions.csv`](partitions.csv) で決まります**（ボードパッケージは、この設定を、Arduino IDE の Partition Scheme より優先します）。IDE の Partition Scheme は、プログラムの大きさの確認にだけ使われるので、2MB 以上のもの（No OTA または Huge APP）を選んでください（既定の 1.2MB のものでは、「スケッチが大きすぎます」になります）。

Partition Scheme は、フラッシュ（4MB）を、プログラムとデータに分ける設定です。No OTA にすると、プログラム用に 2MB（現在の使用量は約 1.3MB）、データ用に約 1.9MB を使えます。データ用の領域は、[基板の中への記録](#気圧の表示最初に開くページ)に使います（30Hz で約 5.5 時間分）。無線での書き換え（OTA）は使っていません。設定値（感度など）の保存先は変わらないので、Partition Scheme を変えても、保存済みの設定は残ります。

arduino-cli を使う場合は、`--fqbn esp32:esp32:esp32c3:CDCOnBoot=cdc,PartitionScheme=no_ota` を指定します。

書き込みは USB-C から行います。認識されないときは、BOOT ボタンを押しながら RESET ボタンを押すと、書き込みモードに入ります。

## ピン割り当て

| 機能 | GPIO | 備考 |
|---|---|---|
| I2C SDA | 4 | BMP581 SDI（プルアップ 4.7kΩ） |
| I2C SCL | 5 | BMP581 SCK（プルアップ 4.7kΩ） |
| LED データ | 10 | R8 330Ω 経由で LED1 の DIN |
| BOOT ボタン | 9 | 表示モードの切り替えにも使う（active low） |
| USB D- / D+ | 18 / 19 | ネイティブ USB（Serial） |
| 電池電圧 | 1 | R9/R10（各 1MΩ）で 1/2 に分圧。ADC で読み（1 分に 1 回測定）、CSV の最後の列に出力 |

BMP581 の I2C アドレスは SDO を GND に接続しているので **0x46** です。見つからなければ 0x47 も試します。

## 動作

約 30Hz（33ms 周期）でセンサを読み、LED を更新します。

1. 気圧を整数のまま、1 次ハイパスフィルタに通す（ゆっくりした変化は消える）
2. 変化量の絶対値が `deltaLimit` 未満なら消灯
3. それ以上なら、変化の向きに応じたパレットで色にする
   - 気圧上昇: 黒青 → 青 → 水色 → 白
   - 気圧下降: 黒赤 → オレンジ → 黄橙 → 白
4. 毎フレーム、色を 1 つずつ後ろの LED へ送る（LED1 が最新）

### 起動時の表示

電源が入ると、できるだけ速やかに（シリアルの接続待ちなどより前に）、全 LED を**白**で点灯します。0.5 秒（`BOOT_WHITE_MS`）以上見せたあと、自己診断として、赤 → 緑 → 青の順に、LED を 1 個ずつ点灯し、通常の動作に入ります。白の明るさは、設定の「LED の明るさの最大値」に従います。電池駆動では、白の全点灯は電流が大きいので、電池が弱いときにリセットされる場合は、明るさを下げてください。

### 表示モード

BOOT ボタンを短く押して、4 種類のモードを切り替えます。

| 番号 | モード | 内容 |
|---|---|---|
| 1（既定） | 標準 | 気圧の変化を表示する。細かい動き（数 cm 〜 1 m）向け。不感帯 50（約 6.6 cm）、感度の上限 753（約 100 cm）、時定数 2^8 |
| 2 | ドライブ | 気圧の変化を表示する。車や電車での移動（大きな高さの変化）向け。不感帯 256（約 4 Pa、約 34 cm）、感度の上限 4096（約 64 Pa、約 5.4 m）。時定数（2^8、約 8.5 秒）と履歴の流れ方は、標準と同じ |
| 3 | カスタム | 気圧の変化を表示する。感度を、[設定モード](#設定モードwi-fi)で変更できる |
| 4 | 固定色 | 全ての LED が、設定した色（HSV）で点灯する。明度を 0 にすると消灯する。設定により、気圧の変化を明度に反映できる（1 標準と同じ感度で、5 個の LED に履歴が流れる） |

1 から 3 は、表示の仕方（LED1 が最新で、LED2〜LED5 に履歴が流れる）が同じで、感度だけが違います。

短押しと長押しは、ボタンを**離したとき**に動作します。

| 操作 | 動作 |
|---|---|
| 短押し | 今のモードの番号の数だけ、LED を 2 秒間、青で点灯する（1 なら LED1 だけ、4 なら LED1〜LED4）。その 2 秒の間に、続けて押すと、次のモードに切り替わる（4 の次は 1）。2 秒たってから押したときは、今の番号を見せるだけで、切り替わらない |
| 長押し（1.5 秒以上） | 設定モード（Wi-Fi）と通常モードを切り替える（[設定モード](#設定モードwi-fi)） |
| 20 秒押し続ける | 全ての LED が、1 秒間、赤く点滅したあと、設定を全て初期値に戻す。ボタンを離すと、再起動して通常モードになる |

20 秒押し続けたときは、表示モード、役割、グループ番号、ハブのチャンネル、装置の名前、ハブの接続先の Wi-Fi、ブラウンアウトの累計も含めて、保存されている値を全て消します。押している途中（1.5 秒から 20 秒の間）は、LED が水色になります。20 秒になる前に離すと、通常の長押しとして、設定モードとの切り替えになります。ボタンを押したまま再起動すると、書き込みモードに入ってしまうため、再起動は、ボタンを離してから行います。

選んだモードは、番号の表示が終わったときに保存され、電源を切っても残ります。

固定色モードで、明度が 0 でないときは、LED が点灯し続けるので、ライトスリープに入りません（[省電力](#省電力ライトスリープ)）。明度を 0 にして、反映量を設定すると、気圧が上がったときだけ光り、消えている間は眠れます。

## 設定モード（Wi-Fi）

スマホから、感度などの設定を変更するためのモードです。Wi-Fi のアクセスポイントとして動作し、設定用の Web ページを開きます。Wi-Fi が回路で正しく動くかの確認にも使えます。

### 入り方と出方

| 操作 | 結果 |
|---|---|
| BOOT ボタンを 1.5 秒以上長押しする | LED が水色になる。そのままボタンを**離す**と、再起動して設定モードに入る |
| 設定ページの「保存して終了」を押す | 保存して、通常モードに戻る |
| もう一度 BOOT ボタンを長押しして離す | 通常モードに戻る |
| ページを閉じて（スマホの画面が消えて）から 10 分たつ | 自動で通常モードに戻る |

設定モードと通常モードの切り替えは、**再起動**で行います。通常モードでは Wi-Fi を一切初期化しないので、無線は完全にオフです。

ボタンを押したまま再起動すると、書き込みモードに入ってしまうため、必ずボタンを離してから再起動する作りになっています。

### スマホから接続する

| 項目 | 値 |
|---|---|
| SSID | `pressure-monitor` |
| パスワード | **なし**（オープン） |
| 気圧の表示 | `http://192.168.4.1/`（設定は、右上の「⚙ 設定」から。`http://192.168.4.1/settings`） |

QR コードを作成して、スマホのカメラで読み取ると便利です。次の文字列を QR コードにしてください。

| 用途 | QR コードにする文字列 |
|---|---|
| Wi-Fi に接続 | `WIFI:T:nopass;S:pressure-monitor;;` |
| 気圧の表示を開く | `http://192.168.4.1/` |

Wi-Fi に接続すると、スマホが接続確認をして、「ログインが必要な Wi-Fi」と判断し、気圧の表示のページを開きます（iPhone では、ログイン画面として表示されます）。開かないときは、ブラウザで `http://192.168.4.1/` を開いてください。

### 気圧の表示（最初に開くページ）

接続したときに、まず見たいのは、気圧の絶対値と変化量です。そのため、最初のページでは、これらを大きく表示し、その下に、グラフを画面いっぱいに描きます。各種の設定は、右上の「⚙ 設定」ボタンから開きます。

| 表示 | 内容 |
|---|---|
| 気圧 | 気圧の絶対値 [hPa]。直近 6 サンプルの平均 |
| 変化量 | ハイパスフィルタの出力 [Pa]。今のモードの感度で計算した値（LED の色のもとになる値）。縦向きのときは、高さに換算した値（1 Pa ≒ 8.5 cm）も表示する |
| グラフ | 「変化量」と「気圧」を切り替えられる。表示する時間は「10 秒」と「60 秒」から選ぶ。変化量のグラフの下の帯は、LED1 の色 |
| 下の行 | 温度と、今の表示モード。右側に、記録のボタン（● 記録、CSV 保存、消去）と、記録した行数 |
| ボタン | 右上の「⚙ 設定」で設定ページを開く。グラフの切り替えボタンの右端の「Wi-Fi を切る」で、確認のあと、設定モードを終了して、通常モード（Wi-Fi オフ）で再起動する（記録中なら、記録はそのまま続く） |

**記録する（基板の中に記録します）:** 「● 記録」を押すと、次の 2 つから選べます。どちらも、気圧のサンプル（30Hz）を、**基板のフラッシュ**に記録します。「CSV 保存」を押すと、基板から CSV（`http://192.168.4.1/log.csv`）をダウンロードします。「消去」で消せます。

| 選択 | 動作 |
|---|---|
| Wi-Fi のまま記録する | このページで、グラフを見ながら記録する。「■ 停止」で止める |
| 記録して Wi-Fi をオフにする（省電力） | 基板が再起動して通常モード（Wi-Fi オフ）になり、記録を続ける。USB に PC がつながっていなければ、LED が消えている間はライトスリープで待機する。止めるときは、BOOT ボタンを長押しして設定モードに入り、このページの「■ 停止」を押す |

| 項目 | 内容 |
|---|---|
| 記録の間隔 | 記録を始めるときに、**1/30 秒**（毎サンプル）、**1 秒**、**30 秒**から選ぶ（前回の選択を覚えている）。1 秒と 30 秒は、その間のサンプル（約 30 個、約 900 個）の平均を記録する。平均するのは、気圧、温度、変化量。LED の表示は、どの間隔でも 30Hz のまま |
| 記録できる時間 | 1/30 秒: 約 5.5 時間（サンプルの差分を詰めて、約 3.3 バイト/サンプル）、1 秒: 約 39 時間、30 秒: 約 48 日（平均 1 つで 14 バイト）。フラッシュのデータ領域は 約 1.9MB。いっぱいになると自動で止まる。長い記録では、電池の持ちの方が先に尽きることがある |
| 記録中の表示 | LED5 が、5 秒ごとに 0.1 秒、**赤く 1 回**点滅する（USB の検出のために起きている時間に合わせるので、ライトスリープを減らさない。明るさの最大値の設定が掛かる） |
| 記録中で、無線が動いているとき | 設定モード（Wi-Fi）や、役割が送信・ハブ（ESP-NOW）のときは、5 秒ごとに、**赤 0.1 秒 → 水色 0.1 秒**の順に点灯する。電池の消費が大きい状態であることを知らせる（無線を使っている間はライトスリープに入らないので、点灯を長めにして、2 色を見分けやすくしている） |
| いっぱいになったとき | LED5 が、5 秒ごとに**黄色で 2 回**点滅する。記録を「消去」するか、新しく記録を始めるまで続く（電源を入れ直しても続く） |
| スマホの画面 | 消えても、別のアプリに切り替えても、基板が記録を続ける。Wi-Fi のまま記録している間は、設定モードが自動で終了しない |
| 設定モードとの切り替え | 記録は続く（再起動をまたいで、続きから記録する） |
| 電源が切れたとき | そこまでの記録は残る（最後の 1 秒ほどは失われることがある）。時刻が分からなくなるので、記録はそこで終わる |
| 次の記録 | 新しく始めると、前の記録は消える（始める前に表示される） |
| 役割が送信・ハブのとき | 記録を始める前のダイアログに、電池の消費が大きくなる旨を表示する。複数台の表示のための無線（ESP-NOW）は、Wi-Fi をオフにしても動き続け、ライトスリープに入らないため（ニッカド電池 2 本で約 5 時間で電池切れになった例がある）。「記録の前に『単体』に切り替える」（既定でオン）のまま記録を始めると、役割を「単体」にして保存する。設定ページの「役割」で戻せる |

CSV は UTF-8（BOM 付き）です。1 行目は `#` で始まるコメント（記録した装置と条件）、2 行目は列の名前、3 行目からがデータです。

```
# pressure-monitor log,name=ps-1a2b3c,mac=..,role=standalone,mode=1 標準,wifi=off,interval=1/30s,start=2026-10-19 11:45:42 UTC+09:00,end=stopped,samples=553621,csv_firmware=2026-10-19
time,unix_ms,elapsed_ms,pressure_hPa,raw,hpf,temperature_C,battery_mV
```

| コメントの項目 | 内容 |
|---|---|
| `name`、`mac` | 装置の名前と、MAC アドレス |
| `role` | 記録を始めたときの役割（`standalone` = 単体、`sender` = 送信、`hub` = ハブ） |
| `mode` | 記録を始めたときの表示モード |
| `wifi` | `off` = Wi-Fi をオフにして記録した、`on` = Wi-Fi のまま記録した |
| `interval` | 記録の間隔。`1/30s` = 毎サンプル、`1s (average)`、`30s (average)` = その間の平均 |
| `start` | 記録を始めた日時（スマホのタイムゾーン） |
| `end` | 記録の終わり方（`stopped` = 「■ 停止」で止めた、`full` = いっぱいで止まった、`power_loss` = 電源が切れた、`recording` = 記録中） |
| `samples`、`csv_firmware` | データの行数と、CSV を作ったファームウェアの版 |

Python（pandas）で読むときは、`pd.read_csv(path, comment='#')` または `skiprows=1` で、1 行目を飛ばしてください。前の版のファームウェアで記録したものは、`name`、`role`、`wifi` が `unknown` になり、`battery_mV` は空欄になります。

| 列 | 内容 |
|---|---|
| `time`、`unix_ms` | サンプルの時刻。スマホのタイムゾーンで表す。1 秒・30 秒の記録では、平均したサンプルの時刻の平均（ほぼ間隔の中央） |
| `elapsed_ms` | 記録を始めてからの時間 [ms] |
| `raw`、`hpf` | 気圧と、変化量（1/64 Pa）。1/30 秒の記録では、変化量は記録せず、CSV を作るときに、基板と同じ計算で気圧から求め直す（表示していた値と同じになる）。1 秒・30 秒の記録では、気圧は間隔の中の平均、変化量は基板の変化量の平均（変化量は速く振れるので、30 秒の平均は 0 に近くなる） |
| `temperature_C` | 温度。約 1 秒ごとの値 |
| `battery_mV` | 電池（AA(+)x2）の電圧 [mV]。1 分ごとに測った値（変わったときだけ記録する）。USB から給電しているときは、電池の電圧ではない |

**iPhone で保存するとき:** Wi-Fi に接続したときに自動で開く「ログイン画面」には、ファイルを保存する機能がありません（CSV が表として開くだけになります）。また、ログイン画面を「キャンセル」で閉じると、iPhone が Wi-Fi の接続をやめてしまうことがあります。そこで、ログイン画面で「CSV 保存」を押すと、「**接続を完了して、ブラウザで保存する**」ボタンを表示します。押すと、基板はその iPhone だけを「ログイン済み」として扱い、iPhone が行う、ネットにつながるかの確認（`captive.apple.com/hotspot-detect.html` など）に「Success」と答えます。ログイン画面の右上が「完了」に変わるので、「完了」で閉じると、Wi-Fi はつながったままになります。そのあと、ふだんのブラウザ（Chrome でも Safari でも）で `http://192.168.4.1/` を開き、「CSV 保存」で「ファイル」アプリに保存できます。ログイン済みの iPhone は、この Wi-Fi をネットにつながるものとして扱うので、保存が終わったら、Wi-Fi を切り替えてください（基板を再起動すると、ログイン済みの扱いは消えます）。Android などのほかの端末の動きは変わりません。ログイン画面かどうかは、ブラウザの識別文字列（User-Agent）に `Safari/` が含まれるかで判断しています。

ファイル名は `pressure-monitor_<装置の名前>_<日時>.csv` です（例: `pressure-monitor_ps-1a2b3c_20261019-142143.csv`）。装置の名前に日本語を使った場合も、そのままファイル名になります。複数台の記録を区別しやすいように、表示ページの下の行と、ブラウザのタブにも、装置の名前を表示します。

データの各行は、桁数をそろえた固定長（88 バイト）です（例: `2026-10-18 12:34:56.789,1792310863620,00012345,1024.3348,06555743,-0000123,+27.34,2512`）。先頭の 0 や + の付いた数値も、Excel などでは、そのまま数値として読めます。固定長にすると、CSV の大きさ（コメントと列の名前 + 行数 × 88 バイト）が、作り始める前に決まるので、スマホが保存の進み具合を表示できます。

**大きい記録の保存:** 5.5 時間分の記録は、CSV で約 52MB になり、保存に数分かかります。「CSV 保存」を押すと、5MB を超えるときは、大きさの目安が表示されます。保存中は、画面の下に「CSV 送信中 12.3 / 52.0 MB（25%、残り約 3 分）」のように進み具合が表示されます（スマホの通知にも表示されます）。保存している間は、設定モードは自動で終了しません。途中で通信が切れると、Android は作りかけのファイルを消すため、0 バイトのファイルが残ることがあります。その場合は、もう一度「CSV 保存」を押してください。

**時刻の正確さ:** 記録を始めるときに、スマホの時計を基板の時計に設定し、その後は基板の時計で数えます。基板の時計は、ソフトウェアの再起動（設定モードとの切り替え）では止まりません。「■ 停止」を押したときにも、スマホの時計を受け取り、その間の基板の時計のずれを、直線で補正します。誤差は、通信の遅れ（数十 ms）程度の見込みです。ただし、ライトスリープ中は、精度の低い内蔵の発振器で時間を数えるので、Wi-Fi をオフにして記録した場合のずれの大きさは、実機で確かめる必要があります。いっぱいで自動で止まったときや、電源が切れたときは、補正はしません。

ブラウザの中ではなく、基板の中に記録するのは、Android の Wi-Fi の「ログイン画面」（接続したときに自動で開く画面）で保存できるようにするためです。ログイン画面は、ブラウザの中で作ったファイル（`blob:`）を保存できません（「保存できませんでした」になります）。一方、ダウンロードのアドレスに、もう一度 Wi-Fi でアクセスして保存する仕組みなので、基板が返す `/log.csv` は保存できます。Chrome で開き直す必要はありません（Android の Chrome は、インターネットにつながらない Wi-Fi ではなく、モバイルデータ通信で `192.168.4.1` を開こうとして、つながらないことがあります）。

フラッシュへの書き込みは、LED への送信を終えてから行います。約 40 秒に 1 回、フラッシュの消去（数十 ms）のために、LED の更新が 1 フレーム遅れることがあります。

**スマホを横向きにすると**、数値とボタンを 1 行にまとめて、グラフを広く表示します。Android の Chrome などでは「全画面」ボタンが表示され、押すと全画面になり、横向きに固定を試みます（iPhone の Safari は全画面に対応していないので、ボタンは出ません）。ページを開いている間は、画面が消えないようにします（Wake Lock）。

データは、WebSocket で、約 100ms ごとに、30Hz のサンプルをまとめて受け取ります（形式は [`monitor_page.h`](monitor_page.h)）。

この基板は、**キャプティブポータル**として動作します。DNS で全ての名前を基板に向け、どのアドレスへのアクセスも設定ページへ転送します。スマホが「インターネットに繋がらない Wi-Fi」と判断すると、登録済みの別の Wi-Fi へ自動で切り替えてしまうため、これを防ぐ仕組みです。

Web サーバには、**非同期**のもの（ESPAsyncWebServer + AsyncTCP）を使っています。iPhone は、接続の直後に複数の接続を同時に開きます。標準の同期 `WebServer` では、これを順番にしか処理できず、応答が遅れて、別の Wi-Fi へ切り替わってしまいました。

iPhone（iOS 26.6）で、接続したまま設定ページが開くことを確認しています。Android での動作は未確認です。

**パスワードについて:** 既定では、パスワードなしです。検証したのは、この条件だけです。近くにいる人は、誰でも接続して、設定を変更できますが、設定モードにいる間だけです。パスワードを付ける場合は、[`config.h`](config.h) の `AP_PASSWORD` に 8 文字以上を設定し、QR コードを `WIFI:T:WPA;S:pressure-monitor;P:<パスワード>;;` にしてください。同じように動くかは、確認が必要です。

SSID は、[`config.h`](config.h) の `AP_SSID` で変更できます。変更したら、QR コードも作り直してください。

### 設定できる項目

設定は、フラッシュに保存され、電源を切っても残ります。

| 項目 | 内容 |
|---|---|
| LED の明るさの最大値 | 0〜255、既定は 192（255 で抑えない）。標準・ドライブ・カスタムに共通。下げると、全体が暗くなる。固定色には掛からない |
| 不感帯（カスタム） | この変化量（1/64 Pa 単位）未満は消灯。既定は 50（約 0.78 Pa、高さで約 6.6cm） |
| 感度の上限（カスタム） | この変化量で白になる。既定は 753（約 11.8 Pa、高さで約 100cm）。広い範囲を見るなら 15000（約 20m） |
| フィルタの時定数（カスタム） | 約 2^n サンプル。既定は 8（30Hz で約 8.5 秒）。大きいほど、ゆっくりした変化まで拾う |
| 履歴を流す間隔（カスタム） | 色を後ろへ送る間隔（フレーム数）。既定は 1（毎フレーム） |
| 色相・彩度・明度（固定色） | 色相 0〜359 度（既定 30）、彩度 0〜100 %（既定 100）、明度 0〜100 %（既定 50） |
| 音色（Modulino Buzzer） | 鳴らさない、キラキラ、さわやか。既定はキラキラ。選ぶと、試しに鳴らす（[音](#音modulino-buzzer)） |
| 音の高さ（Modulino Buzzer） | 高い（1 オクターブ上）、標準、低い（1 オクターブ下）、とても低い（2 オクターブ下）。既定は標準。ブザーは高い音ほど大きく鳴るので、音量も変わる（高いほど大きい）。選ぶと、試しに鳴らす |
| 気圧の変化を明度に反映する量（固定色） | 0〜100 %、既定は 0（反映しない）。フィルタの出力（1 標準と同じ感度。0.78 Pa 未満は 0、11.8 Pa 以上で ±1）を掛けて、明度に足す。気圧が上がると明るく、下がると暗くなる |

固定色の明度は、「明度 + 反映量 × フィルタの出力」を、0〜100 % に収めた値です（LED の明るさの最大値は掛けません）。たとえば、明度 50、反映量 50 なら、静かなときは 50 %、気圧が大きく上がると 100 %、大きく下がると 0 % になります。明度 30、反映量 100 なら、上がると 100 % まで明るくなり、下がると 0 %（消灯）になります。LED1 が今の明るさで、LED2〜LED5 には、1 標準と同じく、過去のフレームの明るさが履歴として流れます。反映量が 0 のときは、全ての LED が同じ色のままです。
| 役割（複数台の表示） | 単体（既定）、送信、ハブ。[複数台の表示（ESP-NOW）](#複数台の表示esp-now)を参照。「保存して終了」で再起動すると有効になる |
| 装置の名前（複数台の表示） | UTF-8 で 16 バイトまで（日本語は 5 文字まで）。既定は `ps-` と MAC アドレスの下 6 桁（例: `ps-1a2b3c`）。ハブの画面と記録で、装置を見分けるのに使う。空欄にすると既定に戻る |
| グループ番号（複数台の表示） | 1〜255、既定は 39。同じ番号の送信の装置とハブだけが、やり取りする。役割が「送信」か「ハブ」のときに表示される |
| ハブのチャンネル（複数台の表示） | 1〜13、既定は 1。ハブが自分でアクセスポイントになるときのチャンネル。役割が「ハブ」のときに表示される |
| ハブの接続先の Wi-Fi（複数台の表示） | SSID とパスワード。ハブのときだけ使う。空欄なら、ハブが自分でアクセスポイントになる。役割で「ハブ」を選ぶと表示され、「変更する」を押すと入力欄が開く |

装置の名前は、役割が「送信」か「ハブ」のときだけ表示されます。普段は「装置の名前: ps-1a2b3c 変更する」の 1 行だけで、「変更する」を押すと入力欄が開きます（スマホの Chrome が、ページを開いたときに入力欄へスクロールしないようにするため）。

設定ページの上部に、表示モードを切り替えるボタン（1 標準、2 ドライブ、3 カスタム、4 固定色）があります。BOOT ボタンと同じく、切り替えたモードが保存されます。

**値を変えると、基板の LED にすぐ反映されます**（スライドバーを動かしている間も、数値を入力している間も、反映されます）。ただし、値は、WebSocket で、1 秒に 30 回まで送られます（LED の更新と同じ周期）。WebSocket が使えないときは、HTTP の POST に切り替わります。反映した値は、「保存」を押すまでの間だけ有効です。保存しないまま再起動すると、元の値に戻ります。感度（カスタム）や色（固定色）の変化は、そのモードのときに見えます。

標準とドライブの感度は固定で、設定モードでは変えられません（明るさの最大値だけが、設定できます）。数値の項目は、スライドバーと数値の入力欄の、どちらでも指定できます。不感帯と感度の上限は、対数の目盛りのスライドバーです。固定色の色は、画面上の見本ではなく、基板の LED で確認してください（LED は、画面より明るく見えるため、見本を載せていません）。

「初期値に戻す」ボタンで、すべての項目を既定値に戻せます（今のモード、役割、グループ番号、ハブのチャンネル、装置の名前、ハブの接続先の Wi-Fi は変わりません）。既定値は、[`settings.cpp`](settings.cpp) の `SETTINGS_DEFAULT` で変更できます。

### Wi-Fi の動作確認に使う

設定モード中は、LED と気圧のセンサが通常どおり動きます。LED5 が状態表示になります。

| LED5 | 意味 |
|---|---|
| 暗い水色 | Wi-Fi は起動していて、スマホの接続を待っている |
| 緑 | スマホが接続している |

設定ページの上部に、次の状況が 1 秒ごとに更新されます。

| 項目 | 見かた |
|---|---|
| 電池 | 現在の電圧と、設定モードに入ってからの最低値 |
| 前回の再起動理由 | `BROWNOUT` なら、電源電圧の落ち込みでリセットされている |
| ブラウンアウト | ブラウンアウトによる再起動の累計 |
| 接続中の端末、空きメモリ | Wi-Fi の動作状況 |

Wi-Fi の送信時は、ピーク電流が大きくなります。電池駆動のときに `BROWNOUT` が出たり、接続が途切れたりする場合は、[`config.h`](config.h) の `AP_TX_POWER` を `WIFI_POWER_8_5dBm` などに下げて試してください。

電池電圧の最低値は、分圧回路のコンデンサ（C12）でならされるため、数 ms の短い落ち込みは捉えられません。落ち込みの影響は、ブラウンアウトの回数で確認してください。

## 音（Modulino Buzzer）

Qwiic コネクタに [Arduino Modulino Buzzer](https://docs.arduino.cc/hardware/modulino-buzzer/)（ABX00108）をつなぐと、LED1 の色（気圧の変化）に合わせて、音のフレーズを鳴らします。起動時に I2C で探し、見つからなければ何もしません（設定ページの状況に「Modulino Buzzer: あり / なし」と表示されます）。

LED1 が点灯している（変化量が不感帯の外にある）間は、1 小節ずつコードを進めながら、アルペジオを鳴らし続けます。不感帯に入る（LED1 が消える）と、鳴っている音もすぐに止めて、無音にします。

| 要素 | 内容 |
|---|---|
| 明るさ | 気圧が上がる（+）ときは明るい C メジャー（Cmaj9 - G9 - Am9 - Em7 - Fmaj9 - Cmaj9 - Dm9 - G9）、下がる（-）ときは暗い C マイナー（Cm9 - Abmaj9 - Ebmaj9 - Bb9 - Fm9 - Cm9 - Dm7(-5) - G7(-9)）の 8 小節の進行。+ と - が入れ替わっても、進行の位置はそのまま（同じ位置のコードを、もう一方の調で鳴らす） |
| 豪華さ（5 段階） | 変化が大きいほど、また長く続くほど、使うコードの音（三和音 → 7 度 → 9 度）、1 小節の音の数（3 → 4 → 6 → 8 → 12）、速さ、音域を増やす。いちばん豪華な段階では、小節の最後に 2 オクターブ上の音を長めに鳴らして飾る。豪華さは、前の小節の間の最大の変化量で決める（小節の途中で一瞬小さくなっても、急に寂しくならない） |
| 続いている時間 | 2 秒、6 秒、15 秒で段階が上がり、豪華さが増す。あわせて、基準の高さを少しずつ上げて（段階ごとに 2 半音）、盛り上げる |
| 同じ音の繰り返しを防ぐ | 無音が 4 秒（`SOUND_RESET_MS`）より短いときは、コード進行の続きから鳴らす。鳴り始めるたびに、基準の高さを少しずらし（コードの音に合わせるので、外れた音にはならない）、音の並びの形も変える。小節ごとにも、2 種類の形と、上がり・下がりを使い分ける |
| 音の高さ | 基準の高さを、変化量の絶対値に比例させる（D5 約 590Hz 〜 E6 約 1.3kHz。`SOUND_BASE_LOW` / `_HIGH`。音の高さの設定でずらす前の値）。小節の始まりに、基準に最も近いコードの音から並べるので、高さが変わっても、つながりが自然になる。圧電ブザーは低い音ほど小さいので、変化が小さいと、音も小さく聞こえる |
| 瞬間的な変化 | 変化量の絶対値が、約 0.33 秒で 1/4 以上（`SOUND_BURST_DELTA`）増えたら、今の小節を打ち切り、コードの音で速く駆け上がる。変化が大きいほど、音が多く（6 → 10 音）、使うコードの音も増える（0.8 秒は続けて鳴らさない） |

| 音色 | 鳴り方 |
|---|---|
| キラキラ（既定） | 速いアルペジオ。豪華さにより、約 133ms 〜 33ms ごと。駆け上がりは約 33ms ごと |
| さわやか | ゆったりした分散和音。豪華さにより、約 200ms 〜 66ms ごと。駆け上がりは約 66ms ごと |

設定ページで音色や音の高さを選んだときは、明るい調の、いちばん豪華な小節を試しに鳴らします。

**音の高さと音量:** Modulino Buzzer は、周波数と長さしか指定できず、本当の意味での音量（同じ高さのまま、音だけを小さくする）は変えられません。設定の「音の高さ」で、全ての音を 1 オクターブ単位でずらせます（高い: +1、標準、低い: -1、とても低い: -2 オクターブ）。圧電ブザーは約 4kHz で最も大きく、低い音ほど小さく鳴るので、音の高さを変えると、音量も変わります。「とても低い」（約 150〜330Hz が中心）では、かなり小さくなります。音の並びの中で高すぎる音（A7 約 3.5kHz を超える音）は、1 オクターブ下げてから、音の高さの設定でずらします。

- 起動してから 3 秒は鳴らしません（フィルタが落ち着くまで。`SOUND_WARMUP_MS`）。風の強い日など、LED がほぼずっと点灯している環境では、ほぼずっと鳴ります。
- 固定色で、気圧の変化を明度に反映しない（反映量 0）ときは、色が変わらないので、鳴らしません。

Modulino Buzzer は、基板上のマイコン（STM32C011）が、圧電ブザー（PKLCS1212E4001、約 4kHz で最も大きく鳴る）を鳴らします。I2C（アドレス 0x1E）で周波数と長さを送ると、その長さだけ鳴らすので、鳴っている間も、本機はライトスリープに入れます。ライブラリ（Arduino_Modulino）は使わず、同じ形式の 8 バイトを直接送っています。音量と音色（波形）は変えられません。Modulino Buzzer 自体の待機電流は、確かめていません（電池の持ちに影響する可能性があります）。

## 複数台の表示（ESP-NOW）

複数の装置の気圧を、1 台のハブに集めて、スマホのブラウザに表示し、記録できます。アプリのインストールは要りません（iPhone、Android とも、ブラウザで使えます）。

```
 送信の装置 ──ESP-NOW──▶ ハブ ──Wi-Fi + WebSocket──▶ スマホのブラウザ
```

ハブのネットワークは、次のどちらかです。

| 方式 | 設定 | スマホから開くアドレス |
|---|---|---|
| ハブが、自分でアクセスポイントになる | ハブの接続先の Wi-Fi を空欄にする（既定） | Wi-Fi `pressure-hub` に接続して `http://192.168.4.1/` |
| ハブが、既存の Wi-Fi（ルーター）に接続する | ハブの接続先の Wi-Fi に、SSID とパスワードを入れる | 同じネットワークから `http://<IP アドレス>/` または `http://pressure-hub.local/` |

ルーターに接続する方式では、スマホは、いつもの Wi-Fi のまま（インターネットにつながったまま）見られます。

### 準備

1. 各装置で、BOOT ボタンを長押しして設定モードに入り、設定ページの「複数台の表示」で、役割と装置の名前を設定します。
   - 1 台を「ハブ」、残りを「送信」にします。
   - 装置の名前は、初期値（`ps-` と MAC アドレスの下 6 桁）のままでも、装置ごとに別の名前になります。設置場所など、分かりやすい名前に変えることもできます。ハブ自身の気圧も、その名前で表示されます。
   - ハブをルーターに接続する場合は、ハブだけ、「ハブの接続先の Wi-Fi」に SSID とパスワードを入れます。送信の装置は、ハブのチャンネルを自動で探すので、Wi-Fi の設定は要りません。
2. 「保存して終了」を押すと、再起動して、選んだ役割で動きます。シリアルに `# role: sender (name ps-1a2b3c, group 39)` のように出ます。

### スマホで見る

**ハブがルーターに接続している場合:** スマホを同じネットワークにつないで、`http://pressure-hub.local/` を開きます。開けない場合（Android など）は、ルーターから割り当てられた IP アドレスで開きます。IP アドレスは、次のどれかで確認できます。

| 確認する方法 | 内容 |
|---|---|
| ハブのアクセスポイントから（PC は不要） | ハブは、ルーターに接続している間も、自分のアクセスポイント `pressure-hub` を立ち上げたままにしています（[`config.h`](config.h) の `HUB_KEEP_AP_WITH_STA`）。スマホをこれにつないで `http://192.168.4.1/` を開くと、ページの上部に「Wi-Fi「…」に接続中: http://192.168.1.23/」のように表示されます。データも、そのまま見られます |
| ハブのシリアル | 接続したときに `#   URL  : http://192.168.1.23/` と出ます。10 秒ごとの `# hub: station ip 192.168.1.23 ch 6, ...` の行にも出るので、シリアルモニタを後から開いても確認できます |
| ハブの設定ページ | 「前回、ルーターに接続したときのアドレス」として表示されます |

ルーターのアドレスで開いたページの上部にも、同じ表示が出ます（ブックマークや、ほかのスマホに伝えるときに使えます）。DHCP で割り当てられるアドレスは、変わることがあります。変わらないようにするには、ルーターの設定で、ハブの MAC アドレス（シリアルの `# hub: connected to ...` の行や、表示ページのハブのカードに出ます）に、アドレスを固定してください。

ルーターに 20 秒（`HUB_STA_TIMEOUT_MS`）以内に接続できなかったときは、ハブは、自分でアクセスポイントになります（下記の手順で開けます）。

**ハブが自分でアクセスポイントになっている場合:**

1. スマホの Wi-Fi で、ハブのアクセスポイント `pressure-hub`（パスワードなし）に接続します。QR コードにする場合は `WIFI:T:nopass;S:pressure-hub;;` です。
2. **Safari や Chrome で** `http://192.168.4.1/` を開きます。
   - 「インターネットに接続されていません」と表示されても、接続を続けてください。
   - Android で開けないときは、モバイルデータ通信をオフにしてください（インターネットにつながらない Wi-Fi を避けて、モバイルデータ通信で開こうとすることがあります）。

どちらの場合も、装置ごとに、LED の色（直近 5 サンプル）、HPF の出力のグラフ（直近 10 秒）、LED1 の色の履歴、気圧、温度、電池電圧、電波の強さ（RSSI）、欠落率が表示されます。3 秒以上受信がない装置は、薄く表示されます。同じ名前の装置が複数あると「名前が重複しています」と表示されます（表示は MAC アドレスごとに分かれます）。

**並べ替え:** 各グラフの左上の ⠿ をドラッグすると、順序を並べ替えられます（マウスとタッチの両方で操作できます）。並び順は、そのブラウザに保存され、再読み込みしても残ります。「名前順に並べる」で、名前順に戻せます。まだ並べ替えたことのない装置は、後ろに名前順で加わります。

同時に表示できるスマホは、4 台までです（[`config.h`](config.h) の `HUB_MAX_CLIENTS`）。

### 記録する

「記録を開始」を押すと、受け取ったサンプル（30Hz）を、ブラウザの中（IndexedDB）に保存します。ページを再読み込みしても残ります。「CSV を保存」で、まとめてダウンロードし、「記録を消去」で消せます。記録はスマホごとに別々です。

```
time,unix_ms,name,mac,seq,dev_ms,hub_ms,pressure_hPa,raw,hpf,temperature_C,battery_mV,rssi_dBm,led_r,led_g,led_b,mode
```

| 列 | 内容 |
|---|---|
| `time`、`unix_ms` | サンプルの時刻。ハブの受信時刻を、スマホの時計に合わせた値（誤差は数十 ms） |
| `name`、`mac`、`seq` | 装置の名前、MAC アドレス、パケットの連番。CSV は UTF-8（BOM 付き）なので、日本語の名前も Excel で開けます |
| `dev_ms`、`hub_ms` | 送信の装置の `millis`、ハブの `millis` |
| `raw`、`hpf` | シリアル出力と同じ（1/64 Pa 単位） |
| `rssi_dBm` | 電波の強さ。ハブ自身のデータは 0 |
| `led_r`〜`led_b` | LED1 の色（明るさの最大値を掛ける前） |
| `mode` | 表示モード（1〜4） |

画面を点けたままにするため、Wake Lock を使います（iOS は 16.4 以降）。画面を消したり、別のアプリに切り替えたりすると、その間は受信も記録もされません。データの量は、6 台で 1 時間あたり約 30MB です。

### 通信の仕組み

- 送信の装置は、30Hz のサンプルを 3 個ずつまとめて、約 100ms ごとに、ESP-NOW のブロードキャストで送ります（80 バイト。装置の名前とグループ番号を含む）。ペアリングは要りません。ブロードキャストは再送しないため、届かなかったパケットは、連番の抜けで、欠落率として表示されます。
- ハブは、受け取ったパケットを、100ms ごとに 1 つのフレームにまとめて、WebSocket で、全てのスマホへ送ります。ハブは、10 秒ごとに、ネットワークの状態、チャンネル、受信数などをシリアルに出します（`# hub: station ip 192.168.1.23 ch 6, rx ... pkt / 10 s`）。
- ハブがルーターに接続すると、ハブのチャンネルは、ルーターのチャンネルになります。そのため、ハブは、0.25 秒ごとに、自分のチャンネルを入れた合図（ビーコン）を、ESP-NOW で送ります。送信の装置は、1〜13 のチャンネルを順に聞いて（1 チャンネルあたり 0.3 秒、最大約 4 秒）、ビーコンが聞こえたチャンネルに合わせます。ビーコンが 3 秒途切れたら、探し直します。ルーターが自動でチャンネルを変えても、追従します。シリアルに `# link: hub found, channel 6` のように出ます。探している間は、送りません。
- ハブが自分でアクセスポイントになるときのチャンネルは、設定ページの「ハブのチャンネル」（1〜13、既定は 1）です。変えるのは、ハブだけで構いません。互いに重ならないのは 1、6、11 です。
- パケットとビーコンには、グループ番号（1〜255、既定は 39）が入っています。送信の装置は、同じグループ番号のハブのビーコンにだけ合わせ、ハブは、同じグループ番号のパケットだけを表示します。

### 展示会場など、ほかの人も ESP-NOW を使う場所では

| 状況 | 対策 |
|---|---|
| ほかの製品が ESP-NOW や Wi-Fi を使っている | そのデータは、形式が違うので、表示には混ざりません。ただし、電波の時間を取り合うので、欠落が増えます。**ハブのチャンネル**を、空いているチャンネルに変えてください（Wi-Fi の混み具合を見るアプリで確認できます） |
| 本機の別のセットが近くで動いている | データが混ざるので、セットごとに**グループ番号**を変えてください。1 つのセットの中では、全ての装置を同じ番号にします |

通信の形式を変えたときは、版の番号（`LINK_VERSION`、今は 3）を上げています。版の違う装置どうしは、互いのデータを無視するので、全ての装置に、同じ版のファームウェアを書き込んでください。
- ハブは、ESP-NOW を取りこぼさないよう、Wi-Fi の省電力（モデムスリープ）を切っています。
- パケットとフレームの形式は、[`link.h`](link.h) と [`hub.h`](hub.h) に書いています。

### ルーターに接続するときの注意

| ネットワーク | 状況 |
|---|---|
| 5GHz だけのネットワーク | 使えません（ESP32-C3 は 2.4GHz のみ） |
| WPA2/WPA3 エンタープライズ、Web で同意するもの（ホテル、会場など） | 使えません |
| ゲスト用のネットワーク（端末どうしの通信を遮断） | ハブは接続できますが、スマホからハブのページを開けません |
| 混雑したチャンネル | ルーターのチャンネルに従うため、選べません。ルーターを管理できる場合は、チャンネルを固定すると安定します |

パスワードは、設定ページに表示しません。変えないときは、空欄のまま保存してください。パスワードのないネットワークにする場合は、「パスワードを消去する」に印を付けて保存します。

### 電源について

送信とハブは、無線を使うため、ライトスリープに入りません。電池の持ちは、単体のときより短くなります（消費電流は未計測です）。ハブは、USB 給電を推奨します。電池駆動で `BROWNOUT` が出る場合は、[`config.h`](config.h) の `LINK_TX_POWER`（送信）、`AP_TX_POWER`（ハブ）を下げて試してください。

## シリアル出力

115200bps の CSV です。毎ティック 1 行出ます。

```
millis,pressure_hPa,raw,hpf,temperature_C,altitude_m,led_value,battery_mV
```

| 列 | 内容 |
|---|---|
| `raw` | 気圧の値（1 LSB = 1/64 Pa）。BMP581 の内蔵温度補正済みの値です |
| `hpf` | ハイパスフィルタの出力（同じ単位）。符号が正なら気圧上昇。表示に使う値 |
| `led_value` | LED1 の RGB の最大値 |
| `battery_mV` | 電池電圧 [mV]。最後に測った値を、毎行出します（測るのは、起動時と、その後 1 分に 1 回）。1000 未満は、電池が入っていない（USB 給電中など）とみなせます |

`#` で始まる行はメッセージです。1 秒ごとに `# perf` の行が出て、処理時間やログの取りこぼしを確認できます。

電池電圧は、CSV の最後の列 `battery_mV` に出力します（`#` の行では出しません）。測定は、起動時と、その後 1 分に 1 回で、次の測定までは、最後に測った値を出し続けます。ADC の誤差は数 % あるので、正確な値が必要なときは、テスターの実測と突き合わせてください。

## 省電力（ライトスリープ）

**USB が接続されていないとき**（電池駆動など）は、ティックの待ち時間を、ライトスリープで過ごします。33ms 周期のうち、処理をしている時間以外は、CPU を止めるだけでなく、チップごと眠らせます。

LED が点灯している間も眠ります（`LIGHT_SLEEP_WHILE_LIT`）。WS2812B は、データを受け取ったあとは、マイコンが眠っても色を保つので、起きてセンサを読み、LED へ送ったら、次のティックまで眠れます（表示は 30Hz のまま）。以前は、点灯している間は眠らなかったため、風の強い日など、LED が点灯している時間が長いと、電池の持ちが大きく下がっていました。

### 眠る条件

次の条件が、すべて揃っているときだけ、眠ります。

| 条件 | 理由 |
|---|---|
| 通常モード | 設定モードは、Wi-Fi が動いているので、眠れない |
| 役割が「単体」 | 送信とハブは、無線を使うので、眠らない |
| 起動から 15 秒以上 | リセットの直後に USB を接続して、書き込みやシリアルモニタを使えるように |
| USB ホスト（PC）が、3 秒以上、見えていない | ライトスリープ中は、USB の通信（Serial）が使えないので、PC に接続されているあいだは、眠らない |
| 検出窓ではない | 5 秒ごとに 400ms は、眠らずに起きている（下記） |
| （`LIGHT_SLEEP_WHILE_LIT` が `false` のときだけ）LED が全て消えていて、履歴にも色が残っていない | 以前の動作。眠って復帰した直後の LED への送信が化けたとき（[トラブルシューティング](#トラブルシューティング)）の確認用 |

全消灯で内容が前回と同じあいだは、LED へ送りません（LED は状態を保ちます）。眠った後の最初の送信は、念のため、同じフレームを 2 回送ります（`LED_RESEND_AFTER_WAKE`）。点灯中も眠るので、点灯している間は毎フレームが対象になり、起きている時間が約 1.5ms 延びます。乱れが出ないことを確かめたら、`false` にすると、さらに省電力になります。

USB ホストの検出には、`Serial.isPlugged()` を使っています。これは、ライトスリープ中は更新されないので、眠った直後の値は使わず、「眠っていない時間」だけで判定します。

USB ホストが見えないときは、誰も読まない CSV と性能計測の出力も、止めます（CPU の時間を節約するため）。

### USB ケーブルを接続するとき

電池駆動で眠っているときに、USB ケーブルを PC に挿すと、眠っている間は、PC から見えません。5 秒ごとの検出窓（400ms）で、基板が起きている間に、PC が接続を始めます。ホストが検出されると、眠るのをやめて、USB が使えるようになります。

認識に数秒かかることがあります。うまく認識されないときは、**RESET ボタンを押してください**（リセットの後の 15 秒は、眠りません）。

### 消費電流の見積もり

ESP32-C3 部分（3.3V 側）の概算です。**実測はしていません。** 処理の時間は、実測した 40MHz での値（約 4.5ms）を元に、80MHz では約 2.5ms と仮定しました。復帰にかかる時間（約 1ms）、眠っている間の電流（約 0.3mA）も、仮定です。

| 構成 | 起きている時間 | 平均電流（概算） |
|---|---|---|
| 40MHz、眠らない（以前） | 33ms（待ちは CPU を止めるだけ） | 約 8mA |
| **80MHz + ライトスリープ（全消灯のとき。現在）** | 約 3.5ms（センサの読み取りだけ。LED へ送らない） | **約 1.1mA** |
| **80MHz + ライトスリープ（LED が点灯している間。現在）** | 約 5.5ms（LED へ 2 回送る分を含む） | **約 2mA**（LED 自体の電流は別） |
| 80MHz、LED が点灯している間（以前。眠らない） | 33ms | 約 12mA |
| 40MHz + ライトスリープ（全消灯のとき） | 約 5.5ms | 約 1.0mA（ただし、LED が緑になる） |

CPU クロックを下げても、ライトスリープと併用するときは、起きている時間が延びるため、ほとんど省電力になりません。また、40MHz 以下では、復帰直後に LED のデータが化けるため（[トラブルシューティング](#トラブルシューティング)）、80MHz にしています。

### モバイルバッテリーで使うとき

**USB-C にモバイルバッテリーをつないで使う場合は、「低電流モード」（微弱電流モード、IoT モードなどの名称）に対応した製品を推奨します。**

モバイルバッテリーの多くは、出力電流が小さい状態が続くと、負荷がつながっていないとみなして、出力を止めます。ライトスリープ中の消費電流は約 1mA と小さいため、このような製品では、数分で給電が止まります。低電流モードに対応した製品では、ライトスリープを有効にしたままで、給電が止まらないことを確認しています。

次の方法も試しましたが、低電流モードに対応していない製品では、給電が止まるのを避けられませんでした（そのため、ファームウェアには入れていません）。

- ライトスリープを無効にする（約 12mA）
- LED をほぼ消灯の状態で点灯したままにする
- 待ち時間に空ループを回し、CPU クロックを 160MHz にする

### 無効にする

[`config.h`](config.h) の `LIGHT_SLEEP_ENABLED` を `false` にすると、ライトスリープが無効になります（常に約 12mA 以上になります）。眠れない状態（エラー）が 5 回続いたときは、自動で無効になります。

## 調整できるパラメータ

表示に関わる項目（LED の明るさの最大値、カスタムモードの感度、固定色）は、[設定モード](#設定モードwi-fi)のページから変更できます。既定値は、[`settings.cpp`](settings.cpp) の `SETTINGS_DEFAULT` です。

次の項目は、[`config.h`](config.h) の定数です。

| 定数 | 既定値 | 意味 |
|---|---|---|
| `TICK_INTERVAL_MS` | 33 | 更新周期（約 30Hz） |
| `CPU_MHZ` | 80 | 通常モードの CPU クロック（設定モードも 80MHz）。40MHz にすると、ライトスリープから復帰した直後に、LED が一瞬緑になる |
| `LOG_EVERY_N` | 1 | ログを何ティックに 1 回出すか |
| `LIGHT_SLEEP_ENABLED` | `true` | USB が接続されていないときの、ライトスリープの有効・無効 |
| `LIGHT_SLEEP_WHILE_LIT` | `true` | LED が点灯している間も眠る。`false` で、点灯中は眠らない（以前の動作） |
| `LED_RESEND_AFTER_WAKE` | `true` | 眠った後の最初の LED への送信を、2 回送る（乱れの対策） |
| `LIGHT_SLEEP_BOOT_DELAY_MS` | 15000 | 起動から、この時間は眠らない |
| `USB_UNPLUGGED_HOLD_MS` | 3000 | USB ホストが、この時間以上、見えなかったら、眠ってよい |
| `USB_PROBE_INTERVAL_MS` / `USB_PROBE_WINDOW_MS` | 5000 / 400 | 眠っている間も、この間隔で、この時間だけ眠らずに起きている（USB の検出窓） |
| `BATTERY_INTERVAL_MS` | 60000 | 電池電圧を測る間隔（ミリ秒） |
| `AP_SSID` / `AP_PASSWORD` | `pressure-monitor` / （空） | 設定モードの Wi-Fi の SSID とパスワード。パスワードが空（または 8 文字未満）のときは、パスワードなし |
| `PORTAL_DIRECT_HTML` | `false` | `false` は設定ページへ転送（302）、`true` は設定ページの HTML を直接返す。どちらも iPhone で動作を確認済み |
| `AP_TX_POWER` | `WIFI_POWER_19_5dBm` | 設定モードの Wi-Fi の送信出力 |
| `LONG_PRESS_MS` | 1500 | 長押しと判定する時間（ミリ秒） |
| `FACTORY_RESET_PRESS_MS` | 20000 | 設定を全て初期値に戻すまで、押し続ける時間（ミリ秒） |
| `SETTINGS_IDLE_TIMEOUT_MS` | 600000 | ページ（表示または設定）を閉じてから、通常モードに戻るまでの時間（ミリ秒）。ページを開いている間は、戻らない |

感度は、BMP581 の静止時のノイズ（`hpf` の振れ幅）に合わせて決めます。ログの `hpf` 列を見て、不感帯が振れ幅より十分大きいか確認してください。

## トラブルシューティング

**電池駆動のときだけ、最後の LED（LED4、LED5）が、点灯し始めに、一瞬緑になる**
USB 接続中は出ず、電池駆動（ライトスリープが働く状態）で出る症状でした。

原因は、**CPU クロックが遅い（40MHz）と、ライトスリープから復帰した直後に、LED へのデータの補充が間に合わず、データが化けること**でした。WS2812B へのデータは、ESP32-C3 の RMT という周辺機能が送りますが、その補充は CPU が行います。復帰した直後は、キャッシュが空で、CPU が遅いと、補充が間に合いません。その結果、データの終わりの部分（最後の LED）が乱れ、緑に見えたと考えています。

実機で、次のように調べて、確認しました。

| 実験 | 内容 | 結果 |
|---|---|---|
| E1 | 復帰してから、最初に送るまでの待ち時間を増やす | 直らない |
| E2 | 同じフレームを送る回数を増やす | 直らない |
| E3 | **CPU クロックを 80MHz にする** | **直る** |

対策として、通常モードの CPU クロックを **80MHz**（`CPU_MHZ`）にしています。眠っている間の電流は、CPU クロックに依存しないので、平均電流は、ほぼ変わりません（[消費電流の見積もり](#消費電流の見積もり)）。ほかに、次の対策を入れています（[`config.h`](config.h)）。

- 全消灯で、前回と同じ内容なら、LED へ送らない（`LED_SKIP_UNCHANGED`）。送信がなければ、化けようがありません。
- 眠った後の、最初の送信だけ、念のため、同じフレームを 2 回送る（`LED_RESEND_AFTER_WAKE`）。
- 以前は、LED が点灯している間は、眠らないようにしていました。80MHz で直ったので、今は点灯中も眠ります（`LIGHT_SLEEP_WHILE_LIT`）。点灯中に色が化けるときは、`false` にすると、以前の動作に戻ります。

なお、LED への電源の電圧は、全 LED を白で点灯しても 3.3V で、緑は出ませんでした。電源の電圧の落ち込みは、原因ではありません。

`CPU_MHZ` を 40 に戻すと、この症状が再発します。

**電池駆動中に USB ケーブルを挿しても、PC に認識されない**
電池駆動で眠っているときは、USB が使えません。数秒待っても認識されないときは、RESET ボタンを押してください。リセットの後の 15 秒は、眠りません。詳しくは、[省電力（ライトスリープ）](#省電力ライトスリープ)を見てください。

**設定モードで Wi-Fi に接続しても、すぐに別の Wi-Fi に切り替わってしまう**
スマホが、この Wi-Fi を「インターネットに繋がらない」と判断して、登録済みの別の Wi-Fi へ移るためです。この基板は、キャプティブポータル（DNS で全ての名前を基板に向け、設定ページへ転送する）と非同期 Web サーバで対処していますが、それでも切り替わる場合は、次を試してください。

- 設定ページを開いている間だけ、スマホの機能（Android の「Wi-Fi の自動切り替え」「モバイルデータへの自動切り替え」、Samsung の「スマートネットワークスイッチ」など）を無効にする
- スマホの Wi-Fi 設定で、`pressure-monitor` を選び直す（iOS では、別のネットワークの「自動接続」を一時的にオフにする）
- 設定が終わったら、スマホの設定を元に戻す

iPhone での挙動を調べるための検証用スケッチが、[esp32c3-captive-portal-test](../esp32c3-captive-portal-test/) にあります。応答の方式（HTML の直接応答、転送、`Success` の応答）を切り替えて、試すことができます。検証の結果も、そちらの README に載せています。

**LED が白のまま変化しない**
Adafruit_NeoPixel と ESP32 のボードパッケージの組み合わせで、全点灯のまま固まることがありました。このスケッチは FastLED を使っています。FastLED は 3.7.0 以降を使ってください。それでもだめなら、[`led_types.h`](led_types.h) の `#include <FastLED.h>` の前に `#define FASTLED_RMT5 0` を置くと直ることがあります。

**BMP581 が見つからない**
起動時に I2C のスキャン結果が出ます。何も見つからなければ、SDA/SCL の配線、3V3、プルアップ、BMP581 のはんだ付けを確認してください。見つかるのに初期化できないときは、CSB が VDDIO にプルアップされているか確認してください（GND だと SPI モードになり、I2C から見えません）。

**コンパイルエラーになる**
`BMP5_ODR_50_HZ` や `BMP5_OVERSAMPLING_*` のマクロ名は、ライブラリのバージョンで異なることがあります。ライブラリの `bmp5_defs.h` で名前を確認してください。`Serial.setTxTimeoutMs()` は、USB CDC On Boot を Enabled にしたときだけ使えます。

**シリアルモニタを開くと基板がリセットされる**
ESP32-C3 のネイティブ USB の通常の動作です。

**シリアルモニタのログが止まる**
Arduino IDE のシリアルモニタで、自動スクロールをオフにしたときなどにログが止まることがありました（原因は未特定）。LED の動作には影響しません。ログを確実に見たいときは、Tera Term などの別のターミナルを使うか、`LOG_EVERY_N` を大きくしてください。

## 補足

- BMP581 は温度補正を内蔵していて、気圧レジスタは補正済みの値です。
- 起動直後は、センサの自己発熱で温度が上がり続けます。ハイパスフィルタがゆっくりした変化を除くので、表示への影響は小さいです。
