# firmware / esp32c3-captive-portal-test

iPhone などが、基板の Wi-Fi に接続したまま、設定ページを開けるかを確認するための検証用スケッチです。本体のファームウェア（[esp32c3-bmp581](../esp32c3-bmp581/)）とは独立しています。

スケッチ: [`esp32c3-captive-portal-test.ino`](esp32c3-captive-portal-test.ino)

次の記事の方式を再現しています。

- [ESP32-C3でキャプティブポータル（Qiita）](https://qiita.com/nak435/items/70223b72ae645c939477)

## 記事の方式

- アクセスポイントは、**パスワードなし**
- DNS で、全ての名前を基板のアドレスに向ける
- **非同期の Web サーバ**（ESPAsyncWebServer + AsyncTCP）で、どのアドレスへのアクセスにも、同じ HTML ページを **200 で直接返す**

本体のファームウェアは、標準の同期 `WebServer` を使い、転送（302）や `Success` の応答を使っています。iPhone では、すぐに別の Wi-Fi へ切り替わってしまったため、どの違いが効いているのかを確認するために作りました。

## 必要なもの

| 項目 | 内容 |
|---|---|
| ライブラリ | **ESP Async WebServer**、**Async TCP**（どちらも ESP32Async 製）、**FastLED**（3.7.0 以降） |
| ボード | ESP32C3 Dev Module、**USB CDC On Boot: Enabled** |

記事の動作確認は、ESPAsyncWebServer 3.6.0、AsyncTCP 3.3.2、Arduino ESP32 Core 3.3.8 です。

## 応答の方式

BOOT ボタンを押す（離す）たびに、方式が切り替わります。LED1〜3 のうち、点灯しているものが現在の方式です。

| LED | 方式 | 内容 |
|---|---|---|
| LED1 | 0 | 全てのアクセスに HTML を 200 で返す（**記事と同じ**） |
| LED2 | 1 | 全てのアクセスを設定ページへ転送する（302） |
| LED3 | 2 | iOS の接続確認だけ `Success` と応答し、他は HTML |

LED4 は、ページのスライダで変えられる色（リアルタイムに反映されるかの確認用）、LED5 は Wi-Fi の状態です（暗い水色 = 接続待ち、緑 = スマホが接続している）。

## 試し方（iPhone）

1. スケッチを書き込み、シリアルモニタ（115200bps）を開く
2. iPhone で、QR コードを読み取るか、Wi-Fi 設定から `pressure-monitor-test` に接続する
   - パスワードなし: `WIFI:T:nopass;S:pressure-monitor-test;;`
3. ログイン画面（キャプティブポータル）が開くか、そのまま接続が維持されるかを確認する
4. 方式を変えるときは、**iPhone の Wi-Fi 設定でこのネットワークを「削除」してから**、BOOT ボタンで方式を切り替えて、接続し直す

iPhone は、一度接続したネットワークの判定を覚えているため、「削除」してからでないと、方式を変えた結果を確認できません。

## 確認してほしいこと

方式ごとに、次を記録してください。

| 確認項目 | 内容 |
|---|---|
| 接続が維持されたか | iPhone が別の Wi-Fi へ移らなかったか。移った場合は、接続からの時間 |
| ログイン画面が出たか | 出た場合、ページが表示され続けたか |
| スライダの動き | LED4 の色が、リアルタイムに変わったか |
| シリアルのログ | `[wifi] station DISCONNECTED` が出た時刻と、その直前の `[http]` の行 |

`[http]` の行には、iPhone がどのアドレスへ、どの順でアクセスしたかが出ます。切り替わる原因の手がかりになります。

## 検証結果（iPhone）

iPhone（iOS 26.6）で、パスワードなしのアクセスポイントに接続して確認しました。

| 方式 | 結果 |
|---|---|
| 0: HTML を 200 で直接返す（記事と同じ） | **成功**。接続したまま、設定ページが開く |
| 1: 設定ページへ転送（302） | **成功**。接続したまま、設定ページが開く |
| 2: iOS の接続確認に `Success` を返す | **失敗**。接続できない |

方式 2 では、iPhone が `captive.apple.com` の確認のあと、`netcts.cdn-apple.com`（UA は `NetworkCTS`）へ 2 回目の確認をします。この確認に HTML を返してしまうため、「本当には繋がっていない」と判断されたと考えられます。

本体のファームウェア（esp32c3-bmp581）では、標準の同期 `WebServer` ではなく、この検証で動いた非同期 Web サーバ（ESPAsyncWebServer）を使い、転送（方式 1）で応答します。

## パスワードを付ける場合

スケッチ冒頭の `AP_PASSWORD` に、8 文字以上のパスワードを設定します。QR コードは、`WIFI:T:WPA;S:pressure-monitor-test;P:<パスワード>;;` にしてください。

記事はパスワードなしで動作しているので、まずは、パスワードなしで確認することをお勧めします。
